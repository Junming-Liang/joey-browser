# 五张收藏卡的运行时扩展

扩展在原版 1115 个数据条目后追加五张独立收藏卡，不替换原卡。资源与运行时需要一起更新。收藏卡只能用于单人游戏；获胜奖励仍只从这五张中抽取，原单局一张、比赛三张的领奖流程保留。

| 卡名 | 内部 ID / 卡组 ID | 属性与数值 | 收藏效果 |
| --- | --- | --- | --- |
| 凉茶 | 1115 / 1950 | 普通魔法 | 成功发动并结算后，使用者获胜 |
| 年糕 | 1116 / 1951 | 地／4星／水族，800 ATK / 2000 DEF | 通常、特殊或反转召唤成功后，召唤方获胜 |
| 大葱 | 1117 / 1952 | 风／4星／植物族，1700 ATK / 1000 DEF | 同上 |
| 猴子 | 1118 / 1953 | 地／3星／兽族，800 ATK / 600 DEF | 同上 |
| 仙人掌 | 1119 / 1954 | 地／4星／植物族，1000 ATK / 2000 DEF | 同上 |

盖放、召唤被无效、凉茶效果被无效均不触发。普通变更表示与被攻击翻开不视为反转召唤。之前的回血、免战破、贯穿、直接攻击及反伤效果已删除；保留原数值和种族信息。

## 实现与复现

`specialize_custom_cards.py` 在原始翻译和已有性能特化之后运行。它核对固定 EXE 与生成代码的来源，逐块校验源码哈希，安装 `custom_cards.rs` 与 29 处受限特化。重复运行不会叠加补丁，未知生成代码会导致检查失败；脚本不改原 EXE。

```sh
python3 games/joey/reverse/specialize_custom_cards.py /path/to/theseus
python3 games/joey/reverse/specialize_custom_cards.py /path/to/theseus --check
```

生成的 `out/joey_cn/custom-cards-provenance.json` 记录规则版本 `joey-five-collectible-cards-v2`、ID、模块哈希及每个生成块的前后哈希。部署内容指纹应纳入这些信息、实际 WASM 和资源摘要。

| 原版地址 | 扩展位置与约束 |
| --- | --- |
| `0x59dbe0`、`0x584d25` | 凉茶复用原普通魔法的合法发动、目标和无效检查；只有新 ID 的成功效果登记胜者，不执行原回血 |
| `0x5ac9af`、`0x5abc48` | 在反转前记录盖放状态；原召唤状态机结束后，检查任务类别、实际场上新卡与正面状态 |
| `0x5bc050` | 原胜负检查入口应用收藏卡结果：`0xa577f4` 的 `0x10` 结束位，以及 `0xa577fa` 的 `0x40` 胜利或 `0x80` 失败位；与原艾克佐迪亚分支相同 |
| `0x5b9f50` | 原每局初始化回调清除收藏卡胜者与反转快照；结果不能带入下一局 |
| `0x5bdb40` | 联机握手前检查主卡组与副卡组，含任一收藏卡则采用原网络异常结束位 `0x20`，不发送卡组，不产生胜负奖励 |

成功触发首先通过 `Host::collectible_event(internal, side)` 播放各自的主题演出；RPC 只让 guest 工作线程有界等待，浏览器页面继续绘制。演出完成或超时后才登记胜者，同次触发不会重复播放。演出本身不宣称实现额外清场、交换生命等规则。

胜者登记保存在执行游戏逻辑的线程中，并绑定当前 guest 内存。游戏的原结果展示、奖励、保存和窗口结束处理继续执行；不把对方 LP 强制写成零，也不伪造艾克佐迪亚五张手牌或专属动画。网络模式 `3` 在登记及正式胜负检查两处禁用收藏效果。浏览器和服务端均独立拒绝这些 ID，并给玩家明确提示。

原网络卡组消息使用 `0xf004` 小端命令头，随后一字节主卡组数量、一字节副卡组数量，再依次存储双方区域的 16 位小端内部 ID。最大主卡组 80、副卡组 15，总长 194 字节。服务器应同时检查长度、数量与两个区域，不能只检查当前可见的主卡组。

## 收藏、存档与奖励

原存档预留 2048 个收藏槽，新卡写入原存档；YDC 使用 16 位卡组 ID。相关列表与计数上界扩大至 1120。固定栈快照保持原长度，使用尾部两字节空隙保留五张新卡的“已查看”标记。原卡全解锁不应顺便发放收藏卡。

胜利奖励保留原 RNG、同次三张去重、NEW 标记、领奖界面和入库存档。联网使用普通卡组获胜也可领取收藏卡，但领取后必须从主、副卡组移除收藏卡才能参加下一场联机。联网奖励只放开原结果状态机的联网跳过条件；正常胜利、异常退出、窗口等待和一次性创建检查均保留。

CPU 魔法选择保留原顺序，在原 Dian Keto 优先级项不能发动后才尝试凉茶，仍经过原合法发动检查。此处只影响单人对手，不赋予网络收藏卡使用权限。

## 验证与限制

```sh
python3 games/joey/reverse/check_custom_cards.py \
  /path/to/theseus /path/to/joey_pc_cn.exe /path/to/extracted-resources \
  /path/to/custom-card-tests
cargo test --offline --manifest-path /path/to/custom-card-tests/Cargo.toml
```

十三项专项测试通过（含演出精确 ID／玩家、只触发一次和非法条件不播放的 host 替身断言）：原 1115 个 ID 的效果和直接攻击路径保持一致，原卡战斗及 CPU 估算寄存器／标志差分通过，新 ID 边界、收藏效果、旧四种能力移除、原奖励确定性、去重与已查看标记均通过。收藏结果与原艾克佐迪亚检查的正式胜负和结束标志逐项对照，双方 LP 保持原值。召唤测试执行真实完成分支，检查盖放、已正面普通变更、无效后卡片已移除及网络模式；外围召唤展示和无效处理使用明确测试替身，不能替代真实交互验收。

本版本已动态核实 Chromium 仙人掌的召唤、原胜利结算、领取收藏卡、保存及重载，以及公网 WebKit 凉茶演出和胜利、公网双引擎原版互换回合。完整验证范围见仓库 `docs/VERIFICATION.md`。以下交互仍需扩大动态覆盖，不能用专项替身测试冒充实机验收：

- 凉茶成功发动、被无效，四怪正常／特殊／反转召唤、盖放、召唤被无效，以及普通变更表示。
- 即时获胜后原结果展示、领奖、退出、再次开局和存档重载；同一胜局只领奖一次。
- 单人、比赛与普通卡组联网获胜只奖励五张收藏卡；败局、平局、中途退出不领奖。
- 联机主卡组或副卡组放入任意收藏卡均无法开局；移除后可正常建房、加入和完成对战。
- 败方先离开时，正常获胜方仍可完成领奖；双方随后可重新建房。
